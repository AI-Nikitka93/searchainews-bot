## Missing Expected Capabilities

### Critical for stated project identity

1. Production freshness is currently broken for the core user outcome. Remote D1 has `items_total=2906` and `scored_total=2906`, but latest item is `2026-05-26T21:40:16+00:00`, about 108 hours old at audit time, while Worker personal/channel windows use 36 hours.
2. Role relevance is still not fully clean. Remote D1 has canonical roles as majority, but still contains `developer`, `ml_engineer`, `founder`, `product`, `legal`, `ops`, and compound values. Compatibility aliases reduce damage, but do not equal a clean product contract.

### High-value improvement

1. Add `/history` or `/search` for already stored corpus. This was already `FUN-003` in the April audit and remains open.
2. Add frequency/topic/source preferences. This was already `FUN-004` and remains open.
3. Publish default Telegram commands, not only RU/EN localized command lists.
4. Add lightweight feedback (`useful / not useful`) or saved items so relevance can be measured.

### Optional enhancement

1. Mini App / WebApp settings surface.
2. Inline mode for sharing/searching from any chat.
3. Operator curation/replay queue for channel posts.

## Functional Suitability Verdict

- **Functional completeness:** medium. The main system pieces exist: source registry, scraper, analyzer, D1, bot, channel, broadcast, diagnostics. But the production core outcome is currently incomplete because no fresh items are eligible for `/latest` or channel posting.
- **Functional correctness:** mixed. Individual probes passed for Worker health, Telegram webhook, D1 readability, config and typecheck. The core data freshness path fails because GitHub scheduled ingestion is disabled.
- **Functional appropriateness:** medium. Developer-first scoring/channel logic is useful and more than decorative, but history/search/preferences/feedback are missing, so users have little control beyond role/language/subscription.

## Functional Summary

- **Functional status:** working runtime, broken fresh-news product outcome.
- **Главный подтверждённый capability surface:** SearchAInews реально умеет собирать, анализировать, хранить и доставлять AI-news через Telegram bot/channel architecture.
- **Главный user outcome:** свежий AI-news digest с impact score и next actions.
- **Главный functional mismatch:** live bot/channel живы, но production D1 сейчас не содержит fresh eligible items, поэтому основной пользовательский сценарий фактически пустеет.
- **Главный suitability риск:** `functional correctness` core outcome зависит от disabled GitHub workflow, а не от здорового always-on product loop.
- **Что не измеряется:** retention, `/latest` usage, feedback/usefulness, EN path adoption, channel quality.
- **Главный следующий шаг:** включить `pipeline.yml`, прогнать свежий pipeline, затем перепроверить `/latest`, channel candidates and channel post freshness.
