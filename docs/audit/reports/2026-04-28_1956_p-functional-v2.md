## Claimed But Not Proven
- README обещает рольовую доставку для `Developer / PM / Founder`, но current user-facing keyboard уже живёт в другой taxonomy: `ai_specialist / ai_developer / ai_enthusiast / ai_beginner`.
- Наличие legacy `bot/` и `run_bot.bat` не доказывает, что именно этот путь является primary runtime; текущий живой путь подтверждён через Worker webhook.
- `.env.example` всё ещё содержит naming drift (`AI Impact Radar`), поэтому env-template уже не отражает честную product surface.
- Канальный flow выглядит развитым по коду, но без прямого просмотра реальных постов в этом аудите его нельзя повышать до `CONFIRMED`.

## Missing Expected Capabilities
- `Critical for stated project identity`: единая и чистая role taxonomy между analyzer output, corpus и Worker delivery отсутствует; рольовая персонализация сейчас доказано частичная.
- `High-value improvement`: у пользователя нет search/history/archive surface, поэтому бот даёт только “сейчас” и не даёт работать с уже увиденным corpus.
- `High-value improvement`: user preferences ограничены ролью, языком и подпиской; нет управления частотой, depth, темами или source classes.
- `Critical only for full productization`: нет единого operator surface для replay/resend/curation scored items и явного контроля над тем, что именно уходит в канал и в личную выдачу.

## Highest-Impact Improvements

### Critical Gaps
1. Почистить role contract end-to-end: один разрешённый список ролей в analyzer prompt, Python analyzer, corpus migration и Worker query path. Сложность: `💛 Средне`
2. Сделать migration/rewrite для scored items с legacy или посторонними ролями (`ml_engineer`, `ops` и др.), чтобы role-based promise перестал быть частично декоративным. Сложность: `💛 Средне`

### Critical Only For Full Productization
1. Добавить operator replay/curation surface для scored items и channel queue, чтобы редактор мог руками переслать, пропустить или перепаковать item. Сложность: `❤️ Сложно`
2. Развести current Worker truth и legacy local bot truth в явный operational contract, чтобы maintenance capabilities не зависели от исторического шума. Сложность: `💛 Средне`

### Before Release
1. Перепроверить bilingual delivery после сегодняшнего fix на реальном English user path; сейчас это исправлено в коде, но не прогнано end-to-end через production message. Сложность: `💚 Легко`
2. Обновить README и env-template под текущую role taxonomy и naming, иначе product promise остаётся функционально вводящим в заблуждение. Сложность: `💚 Легко`

### High ROI Additions
1. Добавить `/history` или `/recent` surface с просмотром уже доставленных items, а не только fresh batch. Сложность: `💛 Средне`
2. Добавить user controls для digest depth и frequency, хотя бы `compact / standard` и `manual only / auto`. Сложность: `💛 Средне`
3. Добавить source/topic preference surface, хотя бы coarse-level toggles `official / research / community`. Сложность: `💛 Средне`

### Optional / Later
1. Добавить feedback loop `useful / not useful` для постепенной настройки scoring и delivery relevance. Сложность: `💛 Средне`
2. Добавить explicit “why you got this” marker, чтобы пользователь видел связь между item и выбранной ролью. Сложность: `💚 Легко`

### Do Not Build
- Не строить сейчас Mini App, payments или тяжёлую admin panel раньше, чем будет вычищен relevance contract и появится history/preferences surface.
- Не расширять taxonomy новыми ролями, пока не устранён drift между старыми и текущими ролями.

## Functional Summary
- **Functional status:** живой AI-news delivery product с реальным ingestion, scoring и Telegram delivery, но с частично сломанной персонализацией и неглубоким user control surface
- **Главный подтверждённый capability surface:** проект реально умеет собирать AI-news corpus, обогащать его AI-оценкой и доставлять результат через Worker bot и channel paths
- **Главный functional mismatch:** ключевое обещание role-based relevance ослаблено drift-ом taxonomy между corpus/analyzer и текущим Worker delivery surface
- **Главный следующий шаг:** сначала выровнять role contract и подтвердить bilingual path после fix, а уже потом наращивать search/history/preferences
