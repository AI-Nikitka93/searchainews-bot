## 9. Что Требует Больших Изменений

### HQA-BIG-001 - Restore the promised “fresh AI news” result

- **Что надо сделать:** re-enable GitHub Actions `pipeline`, run ingestion/analyze/push, then confirm `/latest` returns fresh items.
- **Почему важно:** ordinary user does not care that webhook is healthy if the main command returns no fresh news.
- **Ожидаемый результат:** after role selection, user taps `10 новостей` and receives current, useful AI news.
- **Вероятные зоны/файлы:** `.github/workflows/pipeline.yml`, GitHub Actions state, `config.yaml`, `ai_analyzer.py`, `scripts/push_to_worker.py`, remote D1.
- **Acceptance criteria:** `eligible_latest_36h > 0`; `/latest` returns items in a real Telegram chat; channel candidates > 0 when inside active hours.
- **Риск, если не сделать:** users conclude the bot is abandoned or fake.

### HQA-BIG-002 - Make the first public surface explain the product

- **Что надо сделать:** set full bot description and short description so `t.me/impactpulse_bot` says what the bot does and who it is for.
- **Почему важно:** first-time users should not need README or author context before clicking Start.
- **Ожидаемый результат:** public profile says, for example, that the bot sends AI news with impact score and next steps for developers/PMs.
- **Вероятные зоны/файлы:** new or extended script for `setMyDescription` / `setMyShortDescription`, bot profile settings.
- **Acceptance criteria:** `getMyDescription.description` non-empty; public `t.me` screenshot shows clear value.
- **Риск, если не сделать:** lower trust and weaker conversion from profile to chat.

### HQA-BIG-003 - Give the no-news state a useful recovery path

- **Что надо сделать:** replace bare “no fresh items” with a human recovery message: explain when updates happen, offer role change, and optionally show last available item or channel link.
- **Почему важно:** empty result without a next step looks like failure.
- **Ожидаемый результат:** user sees why there is no news and what to do next.
- **Вероятные зоны/файлы:** `cf_worker/src/utils/i18n.ts`, `cf_worker/src/bot.ts`, possibly `news.ts` fallback logic.
- **Acceptance criteria:** no-news state includes a clear next action and does not leave user at a dead end.
- **Риск, если не сделать:** every stale pipeline episode becomes a visible user-trust failure.
